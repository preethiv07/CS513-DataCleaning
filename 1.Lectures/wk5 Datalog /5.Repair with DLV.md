# Lecture: Repair with DLV – Logic-Based Database Repair

## ✅ Summary

This lecture demonstrates how to use **DLV (a Datalog + ASP system)** to detect and repair **integrity constraint (IC) violations** in relational databases, with a focus on **functional dependencies (FDs)**.

Key concepts:
- **DLV** extends Datalog with disjunctions (`OR`) and **Answer Set Programming (ASP)** capabilities to model **multiple repair scenarios**.
- Violations are detected using **soft constraints** (queries that identify problems).
- Repairs are generated using **disjunctive rules**: for a conflicting pair, **one value must be deleted**.
- The system **enumerates all possible "worlds"** (repairs) where the ICs are satisfied.
- The approach aims for **minimal repairs**: smallest changes that restore integrity.

---

## 📚 Details

### 🔸 Step 1: Detecting Violations

- **Functional Dependency Example**:
  - FD: `ID → Name` (ID must uniquely determine Name)
  - Violation:  
    - `101 → John Bell`
    - `101 → Joe Logan`
  - Detected by:
    ```prolog
    icv_fd(X, Y, Z) :- student(X, Y), student(X, Z), Y != Z.
    ```
- Output: Conflicting pairs reported (e.g., `bell vs logan`).

---

### 🔸 Step 2: Expressing Repairs in ASP

- ASP allows **disjunctions** in rule heads:
  
  delete(Y) v delete(Z) :- icv_fd(X, Y, Z).

	•	Meaning: “Either Y or Z must be deleted to restore FD.”
	•	This generates multiple repair options (possible worlds):
	•	World 1: Delete bell, keep logan
	•	World 2: Delete logan, keep bell
	•	World 3: Delete ball, keep bell (if ball also shares ID)

## 🔸 Step 3: Repair Execution
	•	Define a new student table:

```
new_student(X, Y) :- student(X, Y), not delete(Y).
```

	•	This creates a “clean” table with inconsistent records removed.

⸻

## 🔸 Step 4: System Behavior
	•	Soft constraints report problems (for review).
	•	Hard constraints (:- icv_fd(X,Y,Z).) can enforce strict rejection of inconsistent worlds.
	•	Silent mode filters outputs for clarity.

⸻

## 🔸 Step 5: Counting Possible Repairs
	•	Each combination of conflicting records creates an exponential number of worlds:
	•	3 conflicting IDs → 3 worlds (each with 2 deletions)
	•	3 IDs + 1 additional conflicting pair → 3 × 2 = 6 worlds

## 🔸 Final Insights

| Concept |  DLV Power |
| --- | --- |
|FD Checking | Queries (icv_fd) detect violations|
| Minimal Repairs | Disjunctive rules generate alternatives|
| Multiple Worlds |  ASP explores all combinations |
| Practical Use | You decide which repair makes sense|

🧠 With great power (DLV) comes great responsibility: repairs are automated, but understanding why they occur and which one to choose is your task.
