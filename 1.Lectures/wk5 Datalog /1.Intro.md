# Lecture: Introduction to Datalog

## ✅ Summary

This lecture introduces **Datalog**, a logic-based query language designed for relational databases. It builds on previous discussions of the relational model, shifting focus from **syntax-level cleaning** to **semantic-level integrity checking**.

Key topics:
- **Relational constraints**: functional dependencies, key constraints, and inclusion dependencies (e.g., foreign keys)
- **Denial constraints**: Datalog’s way to express "bad situations to avoid"
- **Datalog rules**: Head (left) ← Body (right); body conditions are evaluated first
- **Safety in Datalog rules**: Every variable must appear **positively** in the body
- Datalog enables logical **data integrity checks** across columns and tables

By the end of this week, you’ll be able to:
- Write **queries and constraints in Datalog**
- Detect and correct logical errors (not just syntactic)
- Understand **Datalog’s logical foundations** before moving to SQL

## 📚 Details

### 🔸 Recap: Why Datalog?

- OpenRefine and regex fix **syntactic issues** (typos, formats)
- But relational data needs **logic checks**:
  - Does a foreign key in one table match a primary key in another?
  - Are there duplicate IDs?
  - Are there contradictory values across columns?

🧠 **Datalog** is a query language based on **first-order predicate logic** but more practical to write and understand.

---

### 🔸 What is a Datalog Rule?

| Part   | Description |
|--------|-------------|
| **Head** (left side) | What we want to derive (the result) |
| **Body** (right side) | The conditions that must be satisfied for the rule to apply |

> Think of the body as a **filter** — only rows that match the body conditions will be used to assert the head.

Example:  
`bad_data(X) :- person(X, Age), Age < 0.`  
This rule finds records in the `person` table where `Age` is negative.

---

### 🔸 Denial Constraints

- Express **bad situations to avoid**:
  - E.g., "No person should have a NULL email."
- Written as a rule that **fails** when the condition is met.

---

### 🔸 Datalog Rule Safety

For a Datalog rule to be **safe**:
- Every variable must appear **positively** in the body
- No "floating" variables that only exist in the head
- If a variable is only negative (e.g., in a `not` condition), it is unsafe

**Why this matters**:
- Safety ensures we can enumerate all variable bindings
- An unsafe rule can lead to infinite loops or undefined results
