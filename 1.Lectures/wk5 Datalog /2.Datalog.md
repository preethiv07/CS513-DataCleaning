# Lecture: Datalog – Integrity Constraints & Repair

## ✅ Summary

This lecture focuses on using **Datalog** for **checking integrity constraints (ICs)** in relational data and introduces the concept of **database repair** when constraints are violated. It builds on previous lessons about the relational model and highlights the power of Datalog for expressing **logical integrity rules** that span multiple columns and tables.

Key ideas:
- **Dirty data** = data that violates logical integrity constraints
- Integrity constraints (ICs) are modeled as **denial constraints** in Datalog: "bad situations that should not happen"
- Types of ICs:
  - **Functional Dependencies (FDs)** → Key constraints
  - **Inclusion Dependencies (IDs)** → Foreign keys
- Datalog rules have a **head** (conclusion) and a **body** (conditions to match)
- **Safe rules**: Every variable must appear **positively** in the body (not just in the head or under negation)
- **Database repair**: Using Datalog + ASP (Answer Set Programming) to find **minimal repairs** when ICs are violated

### 🔸 Integrity Constraints (ICs) in Datalog

| Type | Description | Example |
|------|-------------|---------|
| **Functional Dependencies (FDs)** | One column determines another (e.g., ID → Name) | No two rows can have the same ID but different Names |
| **Inclusion Dependencies (IDs)** | Foreign keys must match primary keys | `Person.ZIP` must match `Address.ZIP` |

Datalog expresses these as **logical rules**:

```
ic_violated(X) :- student(X,Y), student(X,Z), Y != Z.
```

*This says: “A violation occurs if the same student X has different values Y and Z.”*

## 🔸 Datalog Rule Structure

|Part | Purpose|
| --- | --- |
|Head| The result we want (e.g., a violation)|
|Body| The conditions to match in the data|

> 🧠 Denial constraints: Write rules to describe “bad situations” that must not exist.

## 🔸 Safety in Datalog
For a rule to be safe:
	•	Every variable must appear positively in the body.
	•	Variables cannot only appear in the head or in negated goals (not clauses).

> Why?
Positive atoms generate values; negated atoms filter them. If a variable only exists in a not, there’s no way to know what values to check.

## 🔸 Database Repair (Datalog + ASP)

**When ICs are violated:**
	•	Datalog + ASP (Answer Set Programming) can compute all minimal repairs.
	•	Example:
	•	FD violation on ID = 101 (3 times) and ID = 104 (2 times) → 6 possible minimal repairs (3 x 2).

ASP extends Datalog with a “generate & test” paradigm:
	•	Generate possible fixes
	•	Check which ones satisfy all constraints
