# Lecture: YesWorkflow

## ✅ Summary

YesWorkflow (YW) is a lightweight tool designed to provide **workflow-like abstraction and provenance support** for scientists who write data-processing scripts in languages like **Python**, **R**, and **MATLAB**—without requiring them to switch to full workflow systems like Kepler or Taverna.

Key benefits of YesWorkflow:
- Allows **annotation of script logic** to expose the conceptual workflow structure
- Produces **workflow diagrams** showing data dependencies and process steps
- Helps clarify **inputs, outputs, and intermediate products**
- Bridges the gap between **script-based** and **workflow-based** data science
- Offers different **diagram views**: process-only, data-only, and combined

---

## 📚 Details

### 🔸 Motivation

- Many scientists prefer scripting (Python, R, MATLAB) over workflow systems due to:
  - Flexibility
  - Familiarity
  - Lower learning curve
- However, scripting lacks:
  - **Abstraction**: hard to grasp the high-level method from code
  - **Provenance**: unclear data lineage and transformation history
- YesWorkflow recognizes:  
  > “Scripts are workflows too.”

---

### 🔸 Core Concept

- Annotate scripts with structured comments to describe:
  - **@BEGIN / @END** blocks for computational steps
  - **@IN / @OUT** annotations for data flow
- Example:
  ```python
  # @BEGIN clean_data
  # @IN raw_data
  # @OUT cleaned_data
  # @END clean_data


  	•	These annotations are not code-executing—they declare conceptual structure, not logic.

⸻

## 🔸 Diagram Views

Once annotated, YW can generate:
	1.	Process View — Shows computational steps (green boxes only)
	2.	Data View — Shows how data products are derived from others (yellow nodes only)
	3.	Combined View — Shows both processes and data (default and most detailed)

Visualization uses Graphviz, an external tool to lay out diagrams.

⸻

## 🔸 Use Cases
	•	Paleoclimate reconstruction scripts in R
	•	SKOPE project: Retrodicting maize agriculture in U.S. Southwest
	•	Open-source scientific publications that pair scripts + data + method

# YW enables:
	•	Transparency for reviewers and collaborators
	•	Reusability by exposing method design
	•	Reproducibility by clarifying process-data relationships

## 🔸 Advantages

| Feature | Benefit|
|-----|----|
| No refactoring required | Works with existing scripts|
|Easy to adopt|Just add comment annotations |
|Supports multiple views|Useful for debugging, review, documentation|
|Flexible granularity|Start with 1 box and expand later|

🔸 Limitations
	•	Requires manual annotation (but light effort)
	•	Prospective provenance only (no execution trace like noWorkflow)
	•	Doesn’t run workflows—only models them

⸻

> 🧠 Think of YesWorkflow as the “conceptual whiteboard” overlaid on your script—declaring what your method is doing without rewriting it.
