# Lecture: Examples of YesWorkflow

## ✅ Summary

This lecture illustrates how **YesWorkflow (YW)** can be practically used to document, visualize, and query the workflow structure of scripts used in scientific domains such as **climate modeling**, **bioinformatics**, and **X-ray diffraction**. Through annotations and directory structure mapping, YW enables researchers to **reconstruct both prospective and retrospective provenance**, even when scripts lack built-in tracking mechanisms. 

Key insights:
- YW supports both simple and complex script workflows.
- Workflows are annotated and visualized using input/output and process blocks.
- **Provenance queries** can trace data lineage by linking conceptual models with file system artifacts.
- **YW-RECON** allows mapping script outputs to models via URI-templates, enabling question-driven exploration of execution traces.

- **MsTMIP** = Multiscale Synthesis and Terrestrial Model Intercomparison Project.

### 🔸 Case Study 3: X-ray Diffraction Workflow

- Implemented in **Python**.
- Workflow simulates a **physical data collection pipeline**.
- Example scenario:
  - Collecting images from samples at different **energy levels** (e.g., 10,000V, 11,000V).
  - Organizing data by sample ID, energy, and frame number.

#### Key Features:
- Prospective model from annotations (`@BEGIN`, `@IN`, `@OUT`).
- Directory structure reflects retrospective provenance.
- **URI-templates** used to map conceptual data items to physical files.

---

### 🔸 YW-RECON: Bridging Prospective and Retrospective Provenance

- **Step 1**: Annotate scripts using YW.
- **Step 2**: Run the script to generate files.
- **Step 3**: Use `YW-RECON` to:
  - Link **outputs to models** via file patterns.
  - Map **folder names** to variable bindings in URI templates.
  - Enable **provenance queries** like:
    - Which samples were used?
    - What energy levels were applied?
    - Where is the original image for a given processed image?

---

### 🔸 Example Provenance Queries Enabled

- 🔍 *Which samples did the script collect images from?*
- 🔍 *What were the energy levels used for a given sample?*
- 🔍 *What raw image corresponds to a processed frame?*
- 🔍 *Which cassette ID led to a specific result?*

These questions are answerable due to:
- Annotations describing **input/output structure**.
- Directory structure encoding **sample, energy, and frame** information.
- URI-templates that **bind runtime artifacts to model elements**.

---

### 🔸 Key Takeaway

> 🧠 **Without modifying the script or instrumenting it**, researchers can reconstruct meaningful provenance using a combination of:
> - Script annotations
> - Folder naming conventions
> - YW's model-driven query capabilities

YW proves that even basic file outputs can yield deep insight into processing history if structured and annotated intentionally.
