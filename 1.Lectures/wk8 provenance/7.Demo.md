# Lecture: YesWorkflow Demonstration

## ✅ Summary

This session offers a hands-on demonstration of **YesWorkflow (YW)** in action, showing how annotations within scripts can produce **interactive workflow diagrams** that model both structure and data flow. The example moves from a basic greeting script to a more complex image transformation pipeline, illustrating how **parameters**, **intermediate data**, and **directory structures** can be semantically captured and queried using YesWorkflow. It also introduces the concept of **URI Templates** for linking script variables to file paths, aiding retrospective provenance tracking.

---

## 📚 Details

### 🔸 Script as a Workflow

- A script is treated as a **box with inputs/outputs**:
  - `@BEGIN`, `@END`: Define step boundaries.
  - `@IN`, `@OUT`: Define data dependencies.
- Annotations must be inside comments (e.g., `# @IN raw_data`).
- Dynamic updates happen as soon as comment tags are properly declared.

---

### 🔸 Greeting Script Example

- Basic example with `print_greeting` step.
- Demonstrates multiple outputs like `greeting` and `happiness`.
- Only outputs declared **at both local and global levels** show up in diagrams.

---

### 🔸 Enhanced Greeting Workflow

- Inputs: `provided_greeting`, `provided_emphasis`, and `emphasis_count`.
- Distinction between:
  - **Parameters** (e.g., `emphasis_count` – changes behavior)
  - **Data** (e.g., greeting text – consumed in computation)
- Script blocks:
  - `emphasize_greeting`: modifies greeting using emphasis.
  - `print_greeting`: outputs result to user.

---

### 🔸 Diagram Views in YW

- **Top-down**, **left-to-right**, or **custom layouts** using Graphviz.
- **Toggles**:
  - Turn off/on data, steps, ports, and titles.
  - View only data, only steps, or both.
- Promotes **clean documentation and visualization** of complex scripts.

---

### 🔸 Realistic Image Processing Workflow

- More extensive code example: includes `initialize_run`, `collect_data_set`, `transform_images`, etc.
- Demonstrates branching:
  - Rejecting bad samples
  - Processing and transforming good samples

---

### 🔸 Use of Parameters & Provenance

- White boxes in diagrams = **parameters**
- Examples include: energy levels, cassette IDs, sample IDs

---

### 🔸 URI Templates

- Used to **map conceptual inputs/outputs to actual file paths**:
  - Example: `/run/raw/{cassette_id}/{sample_id}/e{energy}` where each `{}` is a dynamic variable.
- Supports automated traceability without modifying the script.
- Enables **provenance queries** like:
  - Which cassette/sample was used?
  - What energy levels were applied?
  - Where is the raw image for a processed output?

---

### 🔸 Group Project Relevance

- Students can:
  - Use YesWorkflow to document their own data cleaning pipelines.
  - Begin with OpenRefine, loading to SQLite, visualizing, and reporting.
  - Model the entire process in a **workflow diagram**, even without a single script.

---

> 🧠 Lesson: By thoughtfully annotating your script, you transform it into a transparent, queryable, and sharable workflow—supporting reproducibility and clarity without changing your actual code.
