# Lecture: Workflow Automation and Provenance

## ✅ Summary

This lecture addresses the **reproducibility crisis** in science, particularly in **computational workflows** for data analysis and data cleaning. It highlights the need for **workflow automation** and **provenance tracking** to ensure reproducible, transparent, and auditable science.

Key ideas:
- Reproducibility is a major issue in scientific research, with failures often linked to:
  - Incomplete documentation
  - Selective reporting
  - Errors in code and data handling
- Workflow systems (like **Kepler**, **Taverna**, **YesWorkflow**) help:
  - Automate data analysis
  - Scale computations
  - Abstract and modularize pipelines
  - Track **provenance** (data lineage and process history)
- **Provenance** is categorized into:
  - **Retrospective**: What happened (logs, traces)
  - **Prospective**: What is expected to happen (workflow diagrams)

## 📚 Details

### 🔸 The Reproducibility Crisis

- Many studies fail to reproduce due to:
  - Lack of transparency
  - Poor documentation of methods and data handling
- Reproducibility studies:
  - **Successful** → increase trust
  - **Failed** → decrease trust but often yield new insights

---

### 🔸 Why Workflow Automation?

**ASAP Model:**
| Letter | Meaning                         |
|--------|----------------------------------|
| A      | **Automation** of tasks and pipelines |
| S      | **Scaling** via parallel computing |
| A      | **Abstraction** for understanding and reuse |
| P      | **Provenance** tracking (history & lineage) |

- Scripts (Python, R, MATLAB) are workflows too, but need augmentation for provenance.
- Workflow systems provide:
  - **Visual modeling** (like flowcharts or DAGs)
  - Easier sharing and adaptation
  - Reuse of components for repetitive tasks

---

### 🔸 Provenance in Workflows

| Type                     | Meaning                                        |
|--------------------------|-----------------------------------------------|
| **Retrospective Provenance** | Logs of what actually happened in execution    |
| **Prospective Provenance**   | Workflow diagram: what is expected to happen |

Provenance helps:
- Trace data lineage
- Debug unexpected results
- Identify which products are affected by problematic inputs

---

### 🔸 Key Functions of a Scientific Workflow System

Adapted from Tim McPhillips’ "Ten Commandments":

1. Automate existing programs and services
2. Schedule tasks efficiently (parallel when possible)
3. Manage data flow between tasks
4. Allow scientists to modify workflows easily
5. Provide **prospective provenance** (predict workflow behavior)
6. Record **retrospective provenance** (track what actually happened)
7. Reveal and query provenance
8. Organize and version data products
9. Enable sharing and publication of workflows
10. Empower scientists to extend and customize automation

---

### 🔸 Real-World Examples

- **Bioinformatics Pipelines**: WATERS workflow, Motif-Catcher, Kepler workflows
- **Ecological Modeling**: Kepler workflows for Kruger Park, tree-ring climate reconstructions
- **YesWorkflow**: Annotates scripts (Python, R, MATLAB) to extract workflow structure and provenance
