# Lecture: From Provenance to Script-Based Workflows

## ✅ Summary

This lecture discusses the challenges and opportunities of integrating **provenance tracking** and **workflow modeling** into the scripting tools (e.g., Python, R, MATLAB) that most scientists already use. While **workflow systems** like Kepler exist, most scientists prefer general-purpose scripting languages for flexibility and familiarity. The **YesWorkflow** tool is introduced as a solution for bridging this gap, providing **workflow abstraction** and **provenance support** directly in scripts.

Key points:
- Scientists widely use **Python, R, MATLAB** for workflows.
- Scripts provide automation but lack:
  - Visual workflow diagrams
  - Provenance support
  - Clear abstraction and modularity
- **YesWorkflow** annotates scripts to:
  - Create workflow diagrams
  - Extract dataflow graphs
  - Support provenance queries

---

## 📚 Details

### 🔸 Why Not Just Use Workflow Systems?

- Workflow tools like **Kepler** and **Taverna** exist but:
  - Have steep learning curves
  - Require component development (e.g., Java actors for Kepler)
  - May not align with scientists’ coding habits
- Scientists prefer:
  - Familiar tools (R, Python)
  - Incremental learning
  - General-purpose languages usable beyond workflows

---

### 🔸 The Problem with Scripts

| Aspect         | Scripts (Python, R, MATLAB)                     |
|----------------|--------------------------------------------------|
| Automation     | ✅ Easily done                                   |
| Scaling        | ⚠️ Requires extra libraries/effort                |
| Abstraction    | ❌ Lacks high-level views                        |
| Provenance     | ❌ No built-in support for tracing data lineage  |

---

### 🔸 The YesWorkflow Approach

- **YesWorkflow (YW)**: A lightweight tool to add **annotations** in scripts.
- Goal: Extract **conceptual workflows** and **dataflow graphs** from scripts.
- Annotations clarify:
  - **Inputs/outputs**
  - **Data dependencies**
  - **Process steps**
- Generates:
  - Visual workflow diagrams
  - Provenance-like information for script execution

---

### 🔸 Real-World Example: SKOPE Project

- Archaeologists and climate scientists reconstruct ancient climates using:
  - Tree-ring data
  - R scripts for climate modeling
- YesWorkflow helps:
  - Understand data dependencies
  - Document the logic of complex analyses
  - Facilitate reproducibility for interdisciplinary projects

---

### 🔸 Why Not Automatic Extraction?

- Fully automatic extraction is **theoretically hard**:
  - Limits of static code analysis (e.g., halting problem)
  - Human intent ≠ low-level code details
- Scientists **think at higher levels**:
  - Not about loops and functions, but about processes and data flows
- YesWorkflow bridges this gap:
  - Scientists annotate scripts with **conceptual intent**
  - YW builds diagrams from annotations, not from raw code analysis
